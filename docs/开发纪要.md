## ⓿ 当前定格：MindMap 语篇正文整篇可编辑（2026-10-11 第四轮，现行 ?t=20261011fix20）

**用户二轮反馈**：①逐段编辑没法整篇快速增删；②点了保存也没保存。→ 第三轮的逐段 contenteditable 重构为**整篇编辑器**。

**实现**（script.js fix20 + index.html）：
- `setMmTextEditable(on)`：contenteditable 加在 **#mmTextBody 容器**上（不再是逐段）——Ctrl+A 全选整篇增删、整篇粘贴替换、回车新段；空态进入编辑会放入一个空 `<p>` 直接开写（整篇快速新增）；退出时若已删空恢复空态提示。CSS 同步改为容器级虚线框 + 空段 `min-height:1.5em`。
- `commitMmTextEdit(persist)`：**dirty 标志**（mmTextEditDirty）贯穿——toggle 退出只收内存保持 dirty，💾保存 时无论 changed 都落库（修"toggle 退出后保存不持久化"）；**整篇删空=清空 mmCustomText 并落库**（修"删不干净"）；**无作业时明确 notify**"未存档：先点 + 创建作业，编辑已暂存内存"（修"保存无反馈"——无作业时 saveMmAnalysisToHw 静默跳过是系统既有行为，此前无任何提示）；返回 changed||persisted 让 toast 如实显示。
- 保存 toast 区分：`💾 已保存：语篇正文（整篇）+ 六步 N 处`。

**验证**（8803 一次性源，已清）：无作业保存出提示 ✓ / 整篇写入→保存→落库 ✓ / Ctrl+A 全删→保存→DB text=''+空态恢复 ✓ / 空态快速新增→保存→落库 ✓ / toggle 退出→保存→仍落库+toast 如实 ✓ / 刷新恢复 ✓。

**注意**：mmAnalysis 优先级仍高于 examIndex 自动提取（改完即为权威版）；全删空后重进 MindMap 若 examIndex 有该题型文本会自动重新提取填入（既有设计，非 bug）。

## ⓿-1 第三轮：MindMap 语篇正文可编辑（2026-10-11，fix18 已被第四轮取代）

**用户需求**：自动识别的 passage text 有小错时，顶部 ✏️编辑/💾保存 也要能改左栏语篇正文（此前只作用于右侧六步区，正文不可改）。

**实现**（script.js `?t=20261011fix18` + index.html 内联）：
- script.js 新增并导出 `AFR.setMmTextEditable(on)`（段落转 contenteditable+容器加 mm-text-editing 类）与 `AFR.commitMmTextEdit(persist)`（按块采集→state.mmCustomText→段号规范化重渲染+Roles块同步；persist=true 时 saveMmAnalysisToHw 落库当前作业当前题型，刷新仍生效——mmAnalysis 优先级高于 examIndex，改完即为权威版）。
- index.html `sixStepsOps.toggleEdit/save` 联动调用上述两函数；toggle 关=仅内存（与六步行为一致），save=落库。Enter 拆段会被按块收集为新段落。
- 样式 `.mm-text-body.mm-text-editing p` 复用六步区橙色虚线框；按钮 title 已注明编辑范围。
- **深坑（已注释在代码里）**：`const AFR = (()=>{...})()` 是全局词法绑定**不在 window 上**——`window.AFR && ...` 守卫恒假（第一版没生效的根因），必须 `typeof AFR!=='undefined'`。另有小坑：commitMmTextEdit 重渲染后要补 setMmTextEditable(false) 清容器类。

**验证**（port 8803 一次性源，已清）：编辑态橙色虚线框+contenteditable ✓ / 错词修正+Enter拆段保存收集 ✓ / Roles块同步段数 ✓ / IndexedDB hw.mmAnalysis[type].text 落库 ✓ / 刷新恢复 ✓ / 保存后编辑类无残留 ✓。注：无作业时 saveMmAnalysisToHw 静默跳过（系统既有行为，测试需先建作业）。

## ⓿-2 第二轮：下拉差异化 + 顶部空白修复 + 合并JSON路由（2026-10-11）

**本轮四项改动**（备份：`index-下拉与风格调整之前.html`）：

1. **Discourse 下拉按板块显隐**：仅 MindMap 显示 Assignment+Class+**Discourse** 三下拉；其余七板块（Of Today/Scores/Review/Composition/Knowledge/Extension/Introspection）只显示 Assignment+Class。实现：index.html `</header>` 后内联脚本，MutationObserver 观察 `#viewTabsContainer` 的 Tab active 变化——同时覆盖 AFR.switchView 与三个模块各自 show() 的全部切换入口，零侵入各 JS。
2. **Extension/Introspection 顶部 102px 空白根因修复**：essay-review.js 注入的 `.main-content{position:relative}` 使两板块 `inset:0` 的定位基准已是 main-content（自身在主头部之下），而两者 fitTop 又叠加了一次主头部高 → 顶到 204px（header 底=102）。修复：bojian.js / introspection.js 的 CSS 均幂等注入 `.main-content{position:relative}`，fitTop 改为"父元素结构判断 + getComputedStyle"（不能用 offsetParent——init 时视图处于 hidden，offsetParent 恒为 null；参省抽屉是 fixed 定位，仍按视口让位主头部）。修复后两板块贴 102px 起，与 MindMap 全幅板块一致；面板类板块（Scores/Review/Knowledge/Composition）仍为 118px（16px 内边距）。
3. **风格统一**：.bj-app / .cx-app 的 font-family 由硬编码 `"Segoe UI","Microsoft YaHei"` 改为 inherit，跟随主题 --font-base。
4. **📦 合并JSON路由导入**：⚙→🤖 Import AI Analysis 现在识别 `{type:'afr-merged', exam, assignment, modules:{analysis, mindmap, essay, bojian}}`——analysis→挂逐题AI分析（同单板块JSON）、mindmap→按题型并入 hw.mmAnalysis、essay→EssayReview._importMerged（静默追加篇目，按 id 去重覆盖）、bojian→Bojian._importMerged（单卷静默追加，同名覆盖）。各板块分发独立 try/catch，单板块失败不影响其余。**两个 _importMerged 开头都先 init()**——合并导入可能先于该板块任何一次打开（DB 未加载会 null 崩溃，已踩过）。

**AI 生成 JSON 命名规范（用户工作流）**：用户发试卷PDF+答案PDF → 调各板块技能生成 → 命名 `考试名称-板块名称.json`（由各板块自己的导入按钮载入）；另生成总包 `考试名称-合并.json`（type:afr-merged，经 ⚙→🤖 一键分发）。Scores（Excel）/Knowledge/Introspection（自动同步）不产 JSON。

**验证**（port 8803 一次性源，测后已清库）：八板块下拉显隐 ✓ / 两板块 top=102 顺序无关（先开谁都对）✓ / 合并导入四板块落位（Review 5题+MindMap 2篇+Composition 1篇+Extension 1卷，IndexedDB+localStorage 逐一核实）✓ / 单板块分析JSON回归 ✓。
